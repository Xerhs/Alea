Integrity

Compute the SHA-256 of the embedded WebAssembly bytes (using the core's own SHA-256) and compare it to the published value. Scope: this covers only the WASM bytes, NOT the HTML/JS wrapper — the authoritative check is hashing the downloaded .html file itself before opening it.

How to verify the download (before opening)
  • Windows: certutil -hashfile alea-web-offline.html SHA256 (or PowerShell Get-FileHash)
  • macOS: shasum -a 256 alea-web-offline.html
  • Linux: sha256sum alea-web-offline.html
Compare the result to the signed SHA256SUMS shipped in the web edition download (its SHA256SUMS.minisig signature), then disconnect the network and open the file from a local file:// path.

Before you begin — read this

This is a browser: the worst general-purpose environment for handling secrets. It is offered for reach and convenience, and it is honest about the cost.

Trust hierarchy: Air-gapped USB (UEFI) > Desktop (hot OS) > Web (hot browser). For any real funds, use the air-gapped USB edition.

What this page CANNOT guarantee, unlike the USB edition:

  • No memory scrub of JS/DOM copies — anything typed or displayed (mnemonic, passphrase) leaves copies in the JS heap this app cannot pin, overwrite, or locate.
  • No control over swap — the OS may page secrets to disk.
  • No control over the environment — browser extensions, other tabs, the JS engine/JIT, screen capture/screen-sharing, and software keyboards / clipboard managers can all observe secrets.
  • No removed OS, no pre-boot execution, no attested entropy source, no watermark-composited display path.

Phase 1 generates no seed. It only rehearses a public vector and verifies foreign material you supply. But pasting a real mnemonic or passphrase to verify it still puts a real secret on the unscrubbable JS heap — so treat this as a hot environment regardless.

The only supported use: download → verify the hash → disconnect the network → open the local file offline.
